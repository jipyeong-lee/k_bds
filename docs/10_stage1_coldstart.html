요약.
  • 현행 콜드스타트는 v3 sft_mixed 다. 데이터는 일반+의료 혼합 train 9,507건이다.
  • v3 는 v2 대비 생성 형식 점수를 0.185 에서 0.909 로 약 5배 올렸다. 평가 조건은 같다(holdout 972건).
  • holdout 정확도는 0.295 에서 0.348 로 +0.053(상대 +18%) 올랐다. 이득은 전부 vl 층에서 나왔다.
  • v2 의 형식 점수 상한은 학습 데이터 결함에서 왔다. v2 데이터 자체의 형식 점수가 0.473 이다.
  • 최대 출력 2,048 토큰에서 콜드스타트는 RL 의 전제조건이다. RL 이득은 콜드스타트가 있으면 +0.16, 없으면 +0.03 이다.
  • 최대 출력 8,192 토큰에서는 기본 모델 holdout(50.45%)이 SFT(42.67%)보다 높다. 기본 모델은 응답이 약 6~9배 길고 형식 준수율이 0.638 이다(00_overview 1.6, kgpu 측정).
  • 따라서 Stage-1 의 역할은 RL 을 가능하게 하는 것이다.

Stage-1 · 콜드스타트 SFT

목적: 기본 모델은 장문 추론(3.5~4.6K 토큰)을 한다. 잘린 응답은 0점이다. 이것이 RL 정체의 원인이다. 그래서 짧은 <think>/<answer> 형식을 SFT 로 먼저 가르친다.

v2 의 결함: 데이터가 형식 점수의 상한이었다 (2026-07-16 발견)

RL 보상의 형식 항은 format_think 다. 이 함수는 앵커 매칭(^<think>…</think>\s*<answer>…</answer>$)과 think 실질 16자 이상을 요구한다. 이 함수를 v2 학습 데이터에 그대로 적용했다.

지표값
v2 데이터의 format_think0.473
구조 위반(</think> 뒤에 장문 후 <answer>)364/727 (50.1%)
<think> 가 사실상 빈 샘플35 (4.8%, 그중 20이 객관식)

원인은 build_rft_coldstart.py:78 의 합격 조건이다. 조건은 AccuracyMix>=1.0 and closed(c) and len(c)<=6000 이다. closed() 는 '</think>' in c 와 <answer> 존재만 본다. 앵커링과 최소 추론 길이 검사가 없다. 당시 롤아웃 로그에는 느슨한 Format 컬럼만 있었다.

선별 규칙도 결함을 키웠다. 규칙은 질문당 가장 짧은 3개다(sorted(set(comps), key=len)[:3]). 객관식에서 가장 짧은 정답은 <think></think><answer>C</answer> 다. 따라서 이 규칙은 추론 없는 찍기를 먼저 고른다. 4지선다에서는 찍어도 25% 가 AccuracyMix 를 통과한다.

결과: 모델은 절반이 틀린 형식을 배웠다. RL 시작 시 FormatThink 는 0.26 이었다. 600 step 후에도 FormatThink 는 0.425 에서 정체했다. 정체의 원인은 RL 이 아니라 초기화 데이터다.

RFT 는 기본 모델이 가끔 맞힌 간결한 정답만 골라 SFT 로 되먹인다. RFT 는 새 정답을 늘리기보다 이미 낼 수 있는 정답의 스타일을 고정한다. 그래서 형식과 간결성을 가르치는 콜드스타트에 맞다.

위 표는 요청한 목표치다. 실제 채택은 9,889건이다. 형식 점수 게이트와 풀 부족 때문이다. VWI 는 difficulty-5 풀이 57건뿐이다. 그래서 목표 3,000 대신 2,390 을 채택했다. 실측 내역은 학습 데이터 표에 있다.

의료 데이터를 넣은 이유: medix_rl_train(Stage-3 데이터) 51,335건은 assistant 가 비어 있다(prompt+solution 만 있다). 그래서 프로젝트에 의료 추론 트레이스가 0건이었다. v1 과 v2 는 일반(clevr/DeepVision) 전용이었다. 그래서 Stage-3 전이를 검증하지 못했다.

설계 규칙 6개는 각각 v2 결함 하나에 대응한다.

  1. 게이트 format_think == 1.0. 느슨한 closed() 를 버렸다. 이 규칙이 v2 0.473 의 원인을 막는다.
  2. OpenMedReason 정답 위치 편향 제거. 정답이 대부분 A 다(4지선다 A=77%, 5지선다 A=86%). 이미지를 안 보고 A 만 골라도 77~86% 다. 보기를 섞을 수는 없다. 추론문의 29.6% 가 option B 처럼 문자를 참조하기 때문이다. 대신 정답 문자별로 균형 샘플링했다(A/B/C/D 각 1,250).
  3. 정답 정규화. VLAA 답은 \boxed 66%, \[..\] 76%, 앞뒤 공백 100% 다. 일부는 <answer> 에 산문을 통째로 넣었다. 정규화 후 200자 초과 답은 뺐다. 이 프로젝트는 \boxed 컨벤션을 폐기했다.
  4. 간결성 상한 6,000자. 콜드스타트의 목적은 잘림 차단이다.
  5. 질문 단위 train/val 분할. v2 는 질문을 정렬한 후 stride 로 나눴다. 그래서 같은 질문의 형제 샘플이 양쪽에 있었다. 이것 때문에 v2 val loss 가 4 epoch 내내 0.2136~0.2149 로 평탄했다.
  6. 난이도 층화. VWI difficulty 1~5 를 균등하게 뽑는다. v2 의 "가장 짧은 것" 선별은 찍기를 먼저 골랐다.

v3 holdout 평가 결과 (job 69807, 2026-07-20)

평가 데이터는 work/data/deepvision_holdout.jsonl 이다. DeepVision-103K 층화 holdout 972건(math 453 / vl 519)이다. scripts/make_holdout.py 로 분리했다. 이 데이터는 학습에 쓰지 않았다. Stage-2 도 deepvision103k_trainonly.jsonl 로 새로 학습했다. 따라서 누수는 0 이다.

학습 중의 sft_mixed_val.jsonl(382)은 holdout 과 다른 셋이다. val 은 학습셋과 같은 분포(질문 단위 분할)이고 eval_loss/token_acc 를 잰다. holdout 은 학습에 쓰지 않은 분포에서 생성 정답률과 형식을 잰다.

절차: sft_mixed_merged 로 병합하고 vLLM 으로 띄워 holdout 972건 전량을 채점했다. 스크립트는 scripts/50_eval_v3.slurm 과 scripts/eval_v3_holdout.py 다. 조건은 temp=0, max_tok 2048, 같은 system 프롬프트다. v2 도 같은 조건으로 다시 쟀다(52_eval_v2_baseline.slurm, job 70671, 2026-07-21).

콜드스타트 Ablation (2026-07-09)

이 실험은 v2 데이터로 했다. 절제 변수는 콜드스타트 init 유무다. 그래서 결론은 데이터 버전과 무관하게 v3 에도 유효하다. v2 는 데이터 형식 점수가 0.473 인데도 필수였다.
  • 계기: 콜드스타트 모델의 HealthBench(0.224)가 기본 모델(0.229)과 동률이었다. 그래서 Stage-1 을 빼도 되는지 확인했다.
  • 설계: 절제 변수는 콜드스타트 init 유무다. 나머지(trainonly, dr_grpo, LoRA, 보상, 하이퍼파라미터)는 같다. 처리군은 기본 모델에서 바로 RL 을 한다(dr_grpo·GDPO 2-arm, step200, 59946/59970). 대조군은 기존 콜드스타트 경로다.
  • 평가: DeepVision 층화 holdout N=200, 최대 출력 2,048.

콜드스타트 없는 RL 은 dr_grpo 0.18, GDPO 0.165 다. GDPO 도 붕괴를 막지 못했다. 표의 0.22 는 당시 소표본 값이다. 같은 조건 전량 재측정 값 0.295 는 v3 holdout 평가 절에 있다.

결론. RL 이득은 콜드스타트에 조건부다(+0.16 vs +0.03). 콜드스타트가 없으면 FormatThink 가 100 step 내내 약 0 에 머문다. 콜드스타트 init 은 FormatThink 0.26 에서 시작한다. 콜드스타트가 없으면 잘림이 40% 이고 학습이 2~3배 느리다. 200 step RL 은 콜드스타트 SFT 한 번(0.22)보다 낮다. HealthBench 동률은 대상 밖 지표(텍스트 의료)의 결과다.

적용 범위. 이 결론은 최대 출력 2,048 토큰 조건의 결론이다. 이 조건에서 Stage-1 은 RL 의 전제조건이다. 최대 출력 8,192 토큰에서는 기본 모델 holdout(50.45%)이 SFT(42.67%)보다 높다(00_overview 1.6).
