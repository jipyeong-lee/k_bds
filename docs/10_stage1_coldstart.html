v2 의 진짜 결함 — 데이터가 형식보상의 천장이었다 (2026-07-16 발견)

RL 이 최적화하는 보상은 format_think(configs/accuracy.py)다. 이 함수는 앵커 매칭(^<think>…</think>\s*<answer>…</answer>$)을 요구한다. 또 think 실질 16자 이상을 요구한다. 이 함수를 v2 학습 데이터에 그대로 돌렸다. 결과는 아래와 같다.

v1·v2 구축 상세 — RFT 콜드스타트 (job 57242, 2026-06-16)

(구 project_status_2026-07-05.md 부록 A 에서 옮김. v2 결함은 위 절 참조.)

왜 필요했나: base(Qwen3.5-9B VL)는 어려운 시각/기하 문제에서 본래 매우 길게 추론한다. 4096/6144 토큰 budget 으로도 ~50% 가 잘린다 → 무답 0점. RL·budget 조정으로는 잡지 못했다. 그래서 간결 추론 습관을 SFT 로 재주입한다.

1차 (plain) 콜드스타트 — 폐기 (v1)

  • 스크립트는 build_coldstart_sft.py 다. 데이터는 UCSC-VLAA/VLAA-Thinking 의 clevr_math 서브셋(~5.9K)이다. answer 가 이미 <think>…</think><answer>X</answer> 형식이라 거의 그대로 썼다 → sft_coldstart_train.jsonl 2913건.
  • 문제: clevr_math 는 너무 쉽다(평균 760자). 어려운 시각/기하 문제로 일반화에 실패했다(여전히 잘림).

RFT란? (Rejection-sampling Fine-Tuning) — 모델이 스스로 만든 답 중 정답인 것만 골라(rejection sampling) 그것으로 다시 SFT 하는 자기증류(self-distillation) 기법이다. 외부 정답 데이터 없이 모델 자신의 성공 사례로 부트스트랩한다.

  1. 생성(sample): 한 문제에 여러 후보 답(롤아웃)을 뽑는다.
  2. 거절(reject): 검증가능 정답과 대조한다. 틀린 것·형식 불량·잘린 것을 버린다.
  3. 정제(curate): 남은 정답에서 중복을 제거한다. 간결한 것 위주로 선별한다.
  4. 재학습(fine-tune): 이 선별셋으로 SFT 한다 → 좋은 습관을 모델에 고정한다. (반복하면 STaR/ReST)

계보: STaR(Zelikman 2022) · ReST(Gulcehre 2023) · RFT(Yuan 2023). 모두 "정답 롤아웃으로 SFT" 골격을 공유한다. RL(GRPO)은 보상 gradient 로 정책을 민다. RFT 는 정답 샘플만 남긴 offline SFT 라 싸고 안정적이다. 단 RFT 는 "정답을 더 잘 내게" 하는 것보다 이미 낼 수 있는 정답을 원하는 스타일로 고정하는 데 강하다 → 콜드스타트(형식·간결성 주입)에 맞다. base 는 어려운 문제도 가끔 맞히지만 장황해서 잘린다 → 그 "가끔 맞힌 간결한 성공"만 골라 되먹인다.

2차 (RFT) 콜드스타트 — v2

  • 스크립트는 build_rft_coldstart.py 다(DeepVision 롤아웃에 RFT 적용). 소스는 자기 GRPO 롤아웃 로그 grpo_general/v*/completions.jsonl 이다.

왜 의료를 넣나: medix_rl_train(Stage-3 데이터) 51,335건은 assistant 가 통째로 비어 있다(prompt+solution 만 있다). 그래서 프로젝트에 의료 추론 트레이스가 0건이었다. v1·v2 는 둘 다 일반(clevr/DeepVision) 전용이었다. 그래서 Stage-3 전이가 미검증 한계로 남아 있었다.

설계에 반영한 6가지 (모두 위 결함에 직접 대응한다)

  1. 게이트 = format_think == 1.0 (느슨한 closed() 폐기) — v2 0.473 의 원인을 차단한다.
  2. OpenMedReason 정답위치 편향 제거 — 정답이 거의 항상 A 에 있다(4지선다 A=77%, 5지선다 A=86%). 이미지를 안 보고 A 만 찍어도 77~86% 다. 보기 셔플은 불가하다. 추론문의 29.6% 가 option B 식으로 문자를 참조하기 때문이다 → 정답 문자별 균형 샘플링(A/B/C/D 각 1,250).
  3. 정답 정규화 — VLAA 는 \boxed 66%·\[..\] 76%·앞뒤공백 100% 다. 일부는 <answer> 에 산문을 통째로 넣었다 → 정규화하고 200자 초과는 배제한다. \boxed 컨벤션은 이 프로젝트에서 폐기됐다.
  4. 간결성 상한 6,000자 — 콜드스타트의 존재이유는 잘림 차단이다.
  5. 질문 단위 train/val 분할 — v2 는 질문 정렬 후 stride 분할이었다. 그래서 같은 질문의 형제가 양쪽에 있었다. 이것이 val loss 가 4에폭 내내 0.2136~0.2149 로 평탄했던 원인이다.
  6. 난이도 층화 — VWI difficulty 1~5 를 균등하게 뽑는다. v2 의 "가장 짧은 것" 선별은 찍기를 우선 선택했다.

콜드스타트 Ablation Study (순가치 확정, 2026-07-09)

v2 데이터 기준이다. 결론은 v3 에도 유효하다. 절제변수가 "콜드스타트 init 유무"이기 때문이다. 즉 데이터 버전과 무관하게 "콜드스타트 없이는 RL 이 형식을 못 배운다"를 보인다. v3 는 이 결론을 더 강화한다. v2 조차 형식 0.473 이었는데도 필수였기 때문이다.

계기: 콜드스타트의 HealthBench(0.224)가 base(0.229)와 동률이었다. 그래서 "Stage-1 을 제껴도 되나?"를 clean ablation 으로 확정했다. 상세는 아래 학습 경과·층별 결과 와 적합성 판단 에 있다(구 stage1_coldstart_assessment.md 에서 옮김).

  • 가설: H1 콜드스타트=RL 전제조건 vs H0 콜드스타트=가속일 뿐.
  • 설계: 절제변수 = 콜드스타트 init 유무. 나머지(trainonly·dr_grpo·LoRA·보상·하이퍼)는 전부 통제했다. base→RL(dr_grpo·GDPO 2-arm, step200, 59946/59970) vs 기존 콜드스타트 경로.

v2 콜드스타트 적합성 판단 (2026-07-08)

(구 stage1_coldstart_assessment.md §2 에서 옮김. 대상 = v2: RFT 727건 · 4 epoch · LoRA r16/a32)

적합하다 — 단 "최소 기능(minimum viable) 콜드스타트"로서 적합하다. 최적은 아니다. 명분(RL 인에이블)은 달성·입증했다. 효율·선별편향·Stage-3 전이에는 개선 여지가 있다.

적합한 점:

  1. 형식 주입 → RL 인에이블 → Stage-2 plateau 돌파(다운스트림 성공이 최종 검증이다).
  2. 1차 clevr_math(쉬움) 실패 후 DeepVision 자기 롤아웃으로 바꾼 판단.
  3. 과적합 없음(val 평탄, token_acc 0.924).

미흡·위험한 점:

  1. 4 epoch 과다 — val 이 epoch 1 에 이미 수렴했다(0.2149→0.2138). 1~2 epoch 로 충분하다(다만 ~5분이라 손실은 미미하다). → v3 는 2 epoch.
  2. "가장 짧은 정답" 선별 → 쉬운 문제 편향 가능성 — 필터가 정답 AND 간결 이라 모델이 이미 잘 푸는 문제에 쏠릴 수 있다. 어려운 문제의 간결화 전이는 간접 증거(FormatThink 5배·홀드아웃 +47%)뿐이었다. → 이후 찍기 편향으로 확인됐다(위 v2 결함).
  3. 727건·DeepVision 전용 — 규모가 작고 도메인이 단일이다. Stage-3(medix) 형식 전이는 미검증이다. → v3 에서 의료 CoT 를 투입했다.
  4. 순가치 clean ablation 부재 — 홀드아웃 정비 후 비교가 없었다. → 위 ablation 으로 해소했다.

권고(당시): 재학습 시 epoch 1~2 + 어려운 문제 비중 상향 + medix 형식 소량 혼합을 검토한다. HealthBench 상세(instr +0.044, 평균 8.9K자, judge 파싱실패 9.9%→5.0%)는 30_stage3_medical_rl.html 에 있다.
