요약

  1. Stage-2 를 도메인 전문가 3종 + 통합 구조로 바꿨다(2026-08-13). DeepSeek-V4 와 Kimi K3 도 같은 구조를 따로 택했다. 혼합 학습은 holdout 전체에서 +8.18pp 를 얻었다(일반 +10.80pp). 의료는 +0.75pp 로 유의한 향상이 없었다(p>0.5). 도메인 전용 학습은 같은 850 step 에서 소스를 1.9~4.9배 더 노출한다(4부).
  2. 콜드스타트 SFT 는 계속 필요하다. 조사한 8개 모델은 모두 RL 앞에 SFT 를 둔다. 형식 태그를 버리면 형식 학습만 사라진다. long-CoT 행동, 출발 정책 품질, 길이 기준선, 시각 주의 유도는 남는다. 과도한 SFT 는 RLVR 을 방해한다(1부 3절).
  3. 2026년 리포트가 가장 많이 지목한 불안정 원인은 학습↔롤아웃 확률 불일치다. 그래서 롤아웃 logprob 불일치 계측(3부 항목 F)을 넣었다(1부 ③).
  4. 코어 알고리즘(손실·advantage·필터링)은 외부 관행과 맞는다. RLVR 은 ≤1 epoch 으로 돌리고 조기 중단한다(2부).
  5. 재설계 항목 A(정확도 보상을 형식에서 분리)와 B(단계형 형식 보상)는 GPU 비용이 없다. 기존 롤아웃을 A+B 로 다시 채점하면 개시 구간 총보상이 −0.324 에서 −0.195 로 오른다(하락 폭 40% 감소). repetition 보상과 언어 일관성 보상은 실측으로 기각했다(3부).
  6. 통합은 학습이 없는 가중치 산술부터 시작한다(계단식 통합). 통합 판정 기준은 통합 전에 정했다(4부 7절).

2. 횡단 패턴 7가지

① 형식 태그는 보상에서 빠지고 채팅 템플릿으로 갔다

이 프로젝트와 가장 직접 관련된 패턴이다.

  • HyperCLOVA X 32B Think(A)는 <think> 태그를 채팅 템플릿에 둔다. 비추론·추론·에이전트·멀티모달 템플릿 4종을 따로 쓴다. 보상의 format 항은 보조 항이다. 이 항은 언어 일관성·반복 억제 항과 같은 급이다.
  • K-EXAONE 2.0(A)은 mid-training 에서 일부러 여러 템플릿을 보여 준다. 목적은 형식에 둔감한 tool-use(format-invariant tool-use)다.
  • GLM-4.1V(B)는 r_format ∈ {0, 0.5}, r_accuracy ∈ {0, 1} 을 쓴다. 형식은 정확도의 절반 값인 독립 항이다.

조사한 모델 중 정확도 보상을 형식 태그에 묶은 사례는 없다. 우리 보상에서는 태그가 없으면 가중치 1.0 의 정확도도 0 이었다. 커밋 2a0458a 가 이 결합을 완화했다.

② 표준편차 정규화를 뺀다

  • EXAONE 4.5(A)는 GRPO 에서 표준편차 정규화를 생략한다. 목적은 학습 안정성이다. 그룹 평균만 빼고 나누지 않는다.
  • 우리 실행은 scale_rewards=gdpo 를 썼다. gdpo 는 보상 함수별 z-score 를 가중합하고 배치 화이트닝을 한다. 사후 분석은 표본 안에서 가중치를 ±15% 바꿔 다시 계산했다. 그 결과로 이 설정을 원인에서 제외했다. 외부 관행은 나눗셈을 빼는 쪽이다.
  • EXAONE 4.5 는 zero-variance filtering 도 쓴다. advantage 가 모두 0 인 그룹을 버린다. 우리 frac_reward_zero_std 평균은 0.0106 이다. 그러나 정확도만 보면 균일 그룹이 붕괴 전 13.8% 다(3부 4절 ⑥). 이 필터는 추가 비용이 없다.

③ 2026년 불안정의 주원인은 학습↔롤아웃 확률 불일치다

우리 구성도 같은 위험이 있다. vLLM colocate + LoRA 구성에서 롤아웃(추론)과 업데이트(학습)는 서로 다른 수치 경로를 쓴다. 우리 붕괴는 180~200 이 아니라 step 899 에서 시작했다. 그러나 확률차가 쌓여 임계를 넘으면 절벽이 생긴다는 형태는 관찰과 맞는다. 그래서 롤아웃 logprob 과 학습 logprob 의 차이 분포를 계측한다(3부 F).

④ 길이는 소프트 패널티가 아니라 하드 예산으로 다룬다

  • Kimi K3(A)는 콜드스타트 모델로 문제별 초기 예산 b₀(x) 를 추정한다. 응답이 예산의 σ 배를 넘으면 이진 비교에서 자동으로 진다. 토큰 임계를 넘으면 보상을 −1 로 덮어쓴다.
  • HyperCLOVA X 32B Think(A)는 길이 제어 RLVR 을 독립 단계로 둔다.
  • ReVisual-R1(ICLR 2026)은 Efficient-Length Reward 를 쓴다.

우리 soft_overlong 은 가중치 0.2 의 연속 감점이다. 붕괴 후 길이는 1,376 에서 3,010 으로 늘었다. 이 항은 연속 감점이라 그동안 보상을 끊지 못했다(구간별 값은 3부 4절 ①). 하드 예산이었다면 보상이 즉시 −1 이 된다.

⑤ 도메인 전문가를 따로 키우고 증류로 합친다

2026년의 가장 큰 구조 변화다. DeepSeek-V4 와 Kimi K3 가 같은 구조를 따로 택했다.

        [단일 모델에 순차 RL]              [2026년 관행]
        base → SFT → RL(일반)          base → SFT ─┬→ RL(일반)   ┐
                   → RL(의료)                      ├→ RL(코딩)   ├→ 온폴리시 증류 → 단일 모델
                   → 뒤 단계가 앞을 잊음            └→ RL(에이전트)┘
  • DeepSeek-V4(B)는 도메인별 SFT→GRPO 전문가를 따로 키운다. 그 뒤 전어휘 KL 온폴리시 증류로 합친다. 토큰 단위 추정 대신 전어휘 손실을 쓰면 전문가끼리 불일치할 때 그래디언트가 안정된다.
  • Kimi K3(A)는 3도메인 × 3추론강도로 전문가 9개를 만들고 MOPD 로 합친다. 학생이 자기 롤아웃을 만든다. 해당 도메인 교사가 토큰별 밀집 보상을 준다.

이 패턴은 우리의 Stage-2(일반) → Stage-3(의료) 순차 구조를 대체한다. 혼합 Stage-2 는 holdout 전체에서 +8.18pp 를 얻었다. 의료는 holdout 을 잰 체크포인트 여섯 곳 모두에서 유의한 향상이 없었다(p>0.5). 혼합 학습은 의료 데이터를 포함했는데도 의료 holdout 을 올리지 못했다.

HyperCLOVA X 32B Think(A)는 GRPO 를 다음과 같이 고쳤다.

  • KL 패널티를 없앤다. 목적은 생성 다양성이다.
  • 상단 클립을 하단 클립보다 크게 둔다(비대칭).
  • 동적 샘플링과 적응 클리핑을 쓴다.
  • 정렬 단계는 PPO 를 쓴다. 근거는 "고정 시간 내 최적화 스텝 수가 GRPO 계열보다 많다"이다.

⑦ 불안정은 대부분 아키텍처 층위에서 잡는다

  • K-EXAONE 2.0(A): 깊은 층 일부 전문가의 활성값이 폭주했다. Clamped SwiGLU(임계 7.0)가 피크 활성을 6,862 에서 48.96 으로 낮췄다.
  • Kimi K3(A): up-projection 앞 RMSNorm 과 Sigmoid-Tanh GLU 가 latent MoE 라우팅 경로의 활성 폭발을 막았다. 극단 희소성(전문가 896개·56배)에서 auxiliary-loss-free 부하 분산이 무너졌다. Quantile Balancing 이 이것을 고쳤다.
  • Kimi K3(A): SigLIP 으로 초기화한 비전 인코더는 gradient norm 이 계속 높고 스파이크가 잦았다. Kimi 는 MoonViT-V2 를 next-token prediction 으로 처음부터 학습해 해결했다.

마지막 항목은 우리와 관련 있다. 우리는 freeze_vit=True 로 비전 타워를 얼린다. 비전 타워를 RL 에 열면 gradient norm 스파이크가 따라올 수 있다.

3. 콜드스타트 SFT 는 여전히 필요한가

필요하다. 다만 SFT 의 주 역할은 형식 학습이 아니다. SFT 를 과하게 하면 해롭다.

(a) 조사한 모델 중 순수 RL-from-base 는 없다. 8개 모델 모두 RL 앞에 SFT 가 있다. Kimi K3 는 이 단계를 "SFT/Cold-Start" 라 부른다. Kimi K3 는 여기서 추정한 b₀(x) 를 뒤 RL 단계의 길이 예산 기준선으로 쓴다. 콜드스타트는 후속 RL 의 하이퍼파라미터도 공급한다.

(b) 2026년 연구는 "SFT 는 많을수록 좋다"를 뒤집었다.

논문발견
SFT Overtraining Predicts Rank Inversion via Entropy Collapse Under RLVRSFT 를 과하게 하면 출력 분포가 저엔트로피로 모인다. 그러면 RLVR 신호가 듣지 않는다. SFT 후 순위와 RLVR 후 순위가 뒤집힌다(rank inversion). 최적점은 최대치가 아니다.
The Synergy Dilemma of Long-CoT SFT and RL (추론 VLM 대상)과도한 long-CoT SFT 는 후속 RL 을 방해한다.

(c) 멀티모달에서는 콜드스타트의 종류가 중요하다. ReVisual-R1(ICLR 2026)은 3단 커리큘럼을 쓴다. 순서는 텍스트 전용 콜드스타트, 멀티모달 RL, 텍스트 전용 RL 이다.

"Lazy Attention Localization" 연구에 따르면 멀티모달 콜드스타트는 시각 주의 범위를 키우지 못한다. 주의 분포가 기본 모델과 거의 같다. 텍스트 전용 콜드스타트는 시각 주의 범위를 뚜렷이 키운다.

우리 Stage-1 은 멀티모달 혼합 콜드스타트(sft_mixed_merged)다. 이 발견이 맞다면 우리 콜드스타트는 시각 주의를 키우지 못했을 수 있다. 이 가설은 의료(pmcvqa) holdout 이 체크포인트 여섯 곳 모두에서 오르지 않은 결과와 맞는다. 확증은 없다.

태그를 버리면 콜드스타트의 어떤 역할이 남는가

콜드스타트의 역할태그를 버리면
① 출력 형식 학습 (<think>…</think><answer>…</answer>)사라진다. 형식이 템플릿으로 가면 SFT 가 가르칠 것이 없다.
② 긴 사고사슬 행동 자체 (태그와 무관)남는다. 기본 모델은 long-CoT 를 끝까지 쓰지 못하고 잘린다(4부 6절). RL 만으로 long-CoT 를 세우면 훨씬 비싸다.
③ RL 출발 정책 품질 (탐색 부담 경감)남는다. 우리 실측에서 형식은 v2 0.185 → v3 0.909, holdout 정확도는 0.295 → 0.348(상대 +18%)이다.
④ 길이 예산 b₀(x) 등 후속 RL 의 기준선 공급남는다 (Kimi K3 방식).
⑤ 멀티모달: 시각 주의 유도남는다. 단 텍스트 전용이 더 나을 수 있다.

①만 사라지고 ②~⑤는 남는다. 우리 Stage-1 실측도 이것을 뒷받침한다. v3 콜드스타트는 형식만 고치지 않았다. holdout 정확도를 0.295 에서 0.348 로 올렸다(상대 +18%). 이 이득은 태그와 무관할 가능성이 높다.

2. 에포크: ≤1 epoch + 조기 중단

RLVR 은 SFT 와 달리 에포크를 많이 돌리지 않는다. 프로젝트 실측은 step600(약 0.064 epoch)에서 포화했다. 외부 근거도 과학습 뒤 조기 중단을 권한다.

  • 《Understanding Diversity Collapse in RLVR via Overtraining》(arXiv 2606.15455, 2026-06)
    • MATH/Qwen2.5-Math-7B 에서 검증 Pass@1 은 ~5 에포크에서 멈춘다. 그 뒤 train 성공률은 68.7% 에서 77.1% 로 오른다. 검증은 ~72% 에서 평평하다.
    • 후반 에포크는 Pass@1 이득 없이 high-k Pass@k(다양성)만 깎는다. 논문은 5 에포크 조기 중단을 권고한다.
    • 논문에 따르면 표준 n=8 설정에서 대부분의 업데이트는 추론 경계를 넓히지 않는다. 이 업데이트는 이미 푸는 문제를 더 학습한다.
    • 기전: 문제별 기여가 포화한다. 그 뒤 업데이트는 능력을 넓히지 않고 선호 궤적에 확률 질량을 모은다(policy sharpening). 결과는 다양성 붕괴다.
  • 프런티어 리포트는 에포크로 세지 않는다. Magistral 과 MiniMax-M1 은 큰 배치, 새 롤아웃, 길이 점증(16k→24k→32k)으로 스텝 단위 학습을 한다. 멈추는 시점은 평가 곡선으로 정한다.

이 프로젝트의 환산(2026-08-02 정정)은 다음과 같다. GRPO 의 per_device_train_batch_size 는 프롬프트가 아니라 completion 수다. generation_batch_size = 1 × 8gpu × accum4 = 32 completions 이다. 프롬프트/step = 32 ÷ num_generations(4) = 8 이다. 확장셋 74,787 ÷ 8 이므로 1 epoch 은 9,348 step 이다. 종전 표기 2,337 은 num_generations 로 나누지 않은 값이었다. step600 은 4,800 prompt, 약 0.064 epoch 이다. 계획한 2,337 step 도 0.25 epoch 이다. 따라서 포화는 에포크가 아니라 스텝 수준에서 생겼다. 실측 확인과 영향은 22_stage2b_mixed_run.html §3 에 있다.

결론: 에포크 상한을 늘리지 않는다. ≤1 epoch 으로 돌리고 50 스텝마다 holdout 을 평가한다. 포화하면 조기 중단한다.

근거는 설계 오류다. --max_steps 는 정지 지점이자 cosine LR 스케줄의 분모다. 2,337 로 잡고 1,200 에서 멈추면 LR 이 끝까지 내려오지 않는다. step 900 의 LR 은 6.77e-6 이었다. 분모가 1,200 이면 1.46e-6 이다. 차이는 약 4.6배다. 재실행에는 실제로 돌릴 step 수를 넣는다.

그러나 소스를 보면 비용이 있다.

# grpo_trainer.py:1245
if self.loss_type in ['grpo', 'sapo']:
    loss = ((per_token_loss * completion_mask).sum(-1)
            / completion_mask.sum(-1).clamp(min=1.0)).mean()      # ← 시퀀스별 길이 정규화

④ 형식 가중치 0.2 는 유지한다

GLM-4.1V 에서 형식은 정확도의 50%(0.5 대 1.0)다. 우리는 20%(0.2 대 1.0)다. 그러나 올리는 것이 항상 옳지는 않다. 형식 가중치는 두 가지를 함께 조절한다. 하나는 형식을 지킬 유인이다. 다른 하나는 형식을 잃었을 때의 낙폭이다. 가중치를 올리면 둘 다 커져 되먹임 고리가 세진다. 우리가 겪은 것은 낙폭 쪽이다. 단계형 보상(B)은 같은 가중치에서 형식 손실 시 낙폭을 절반으로 줄인다. 그래서 0.2 를 유지하고 단계형부터 넣는다.

⑤ 보상 항의 영향력은 advantage 분산 점유로 본다

GRPO 는 그룹 평균을 뺀다. 따라서 보상 항의 실제 영향력은 가중치가 아니라 가중치 × 그룹 내 SD 다. 그룹은 프롬프트 1개 × 4생성이다. 로그에서 연속 4칸이 한 그룹임을 확인했다.

4. 전이되지 않을 수 있는 것

  • 규모 차이: DeepSeek-V4 는 1.6T MoE(49B 활성)다. 우리 학습 파라미터는 43M(9B 의 0.48%)이다. 전문가 분리는 용량이 충분할 때 간섭을 푸는 방법이다. 같은 크기의 이득을 기대할 근거는 없다.
  • 도메인 이질성: DeepSeek 의 수학·코딩·에이전트·지시는 행동 자체가 다르다. 우리 세 소스는 모두 이미지를 보고 추론해 객관식 또는 단답을 낸다. 간섭이 처음부터 작았을 수 있다. 그러면 분리 이득은 작고, 병합은 쉽다(계단 0 이득이 크다).
  • 통합 용량: 어댑터 3개의 행동을 같은 rank 16 공간에 넣어야 한다. 그래서 계단 1 학생의 rank 를 32~48 로 올린다. 메모리 비용은 무시할 수 있다.
  • 원저자도 전문가 대 통합 모델 비교를 공개하지 않았다. 통합의 손실률은 우리가 직접 잰다.

vLLM 롤아웃에는 dropout 이 없다. 학습 쪽 logprob 계산에는 dropout 이 켜져 있다. 그래서 π_rollout ≠ π_train 이 구조적으로 생긴다. 이것은 1부 ③과 같은 계열의 불일치다. 이 불일치는 우리 설정이 만들었다. 이 잡음은 3부 F 계측도 오염시킨다. dropout 잡음과 실제 vLLM/HF 수치 격차를 구분할 수 없다.

중요도 비율(ratio)은 영향이 없다. old_policy()(:1927)는 num_iterations=1 이고 grad_accum(4) % steps_per_generation(4) == 0 이라 False 를 반환한다. 그래서 old_per_token_logps 를 따로 구하지 않고 per_token_logps.detach() 를 쓴다(:1152). 같은 forward 라 비율은 정확히 1 이다. 문제는 세 가지다. 첫째, 최적화하는 정책과 샘플링한 정책이 다르다. 둘째, KL 항을 오염시킨다. 셋째, 그래디언트 분산이 는다. 비용이 0 이므로 전문가 3개 모두 --lora_dropout 0 을 쓴다.

rank 를 올릴 때는 --use_rslora true 를 같이 켠다. alpha 스케일이 1/r 대신 1/√r 이라 고랭크에서 업데이트가 지나치게 작아지지 않는다. r=16 에서는 use_rslora=False 로 문제없다.

  • FormatThink 가 100 step 내내 ~0 에 머물렀다(콜드스타트는 0.26 에서 시작).
  • 잘림이 40% 였다.
  • 학습이 2~3배 느렸다.
  • 200 step RL 이 콜드스타트 SFT 한 번(0.22)에도 못 미쳤다.

ablation 의 교란 요인

당시 보상은 정확도가 형식에 묶여 있었다. 기본 모델은 <answer> 태그를 내지 못해 letter 경로가 구조적으로 0 이었다(_LETTER_PICK 의 ^ 앵커). 형식 점수도 0 이었다. 보상이 통째로 0 이라 학습 신호가 없었다. 실패 원인은 "RL 이 기본 모델에서 못 배운다"가 아니라 "보상이 아무것도 주지 않았다"일 수 있다. 커밋 2a0458a(정확도 폴백)와 단계형 형식 보상(3부 B)이 이 구간을 고친다. 따라서 ablation 의 격차는 실제보다 클 수 있다.

그래도 두 가지는 남는다.

  1. 장문과 잘림은 보상으로 고치지 못한다. 기본 모델은 본래 3.5~4.6K 토큰을 쓰고 잘림이 40% 였다. 잘린 응답에는 결론이 없어 폴백도 뽑을 답이 없다. 이것은 초기화 수준의 성질이다.
  2. 학습이 2~3배 느리면 예산이 끝난다. step 당 330 s(재현 실험 74583 실측)에 2.5배를 곱하면 1,000 step 은 229 벽시계 시간이다. 전문가 3개면 5,500 GPU-h 로 당시 잔여 4,126 GPU-h 를 넘는다.

결정: 전문가 3개의 출발 모델은 SFT 모델(sft_mixed_merged)로 유지한다. ablation, 예산, 기준선(ck-850 이 SFT 모델에서 출발) 세 가지가 같은 방향을 가리킨다. DeepSeek-V4 도 기본 모델에서 바로 RL 하지 않는다. 리포트는 "base model first undergoes SFT on high-quality, domain-specific data" 라고 적는다. DeepSeek 은 도메인별 SFT 를 쓰므로 혼합 SFT 하나인 우리보다 SFT 가 많다.

5부 · Stage-2 데이터 (RLVR 풀확장) — 구축과 빌드 런북

요약 (5부·6부)
  1. 방법론: GRPO 변형 5종을 clean A/B 로 비교했다. dr_grpo 가 이겼다. dr_grpo 는 학습 정확도 정체(plateau)를 넘었다. holdout 은 +73% 올랐다(0.22→0.38). GDPO 는 dr_grpo 와 동률이다(step600 holdout 0.390 vs 0.380). GDPO 는 Stage-3 용으로 권고한다. GSPO 는 holdout 이 0.290 으로 낮아 채택하지 않는다.
  2. 포화: holdout 은 step600 근처에서 0.38~0.39 로 포화한다.
  3. 데이터: DeepVision 단일 셋에 MMK12(수학)와 PMC-VQA(의료)를 더했다. 확장 train 은 74,787건(일반 53 / 수학 20 / 의료 26)이다. holdout 은 1,772건이다. 이미지 바이트 해시 dedup 으로 누수는 0 이다.
  4. 이후: 확장셋 혼합 GRPO 는 step ~900 에서 붕괴했다. 이 경로는 폐기했다. 현재 경로는 도메인 전문가 3종 + 통합이다.

3. 심층 분석 결과

정답 형식 분포(검증 가능성):

  • DeepVision: 49.5% MC letter + 27.8% int + 11.5% 수식이고, 43% 가 math_verify 대상이다. MC 가 절반(49.5%)이고 고유 답은 8% 다. 이 낮은 정보량이 step600 포화의 원인일 수 있다.
  • MMK12: int 46.5% + 수식 26.2% 로 82% 가 math_verify 대상이다. 100% 수학이고 고유 답은 32% 다. math_verify 대상 비율(82%)이 후보 중 가장 높다. 언어는 영어 번역본이다. 15,616건 중 한자 잔존은 52건(0.3%)이다. 대부분 甲乙(물체 A/B)·保留(반올림 지시) 같은 자투리다.
  • PMC-VQA: MC 4지선다이고 Answer_label 이 한 보기에 몰리지 않는다(B 54K/C 51K/A 43K/D 28K). OpenMedReason 은 반대로 A 에 77% 가 몰려 있다.
  • ThinkLite: 34% 가 수치, 61% 가 짧은 문자열(times/장소/Yes-No 11%)이다. 다양성은 있지만 노이즈가 크다.

reward 견고성 실측: accuracy_mix 가 "맞지만 형식이 다른" 답을 0점 처리하는지 12케이스로 시험했다. 오채점은 0/12 였다. 콤마(2,380↔2380)·분수(3/4↔0.75)·단위·시간·대소문자·Yes/No 모두 1.0 을 받았다. math_verify + casefold 가 이미 견고하다. 문자열 정규화는 필요 없다.

의료 VQA 공통 함정: 4종 중 2종(VQA-RAD 49%, PathVQA 48%)은 Yes/No 가 절반 가까이다. 이 문항은 추측만으로 절반을 맞힌다. 다양성도 낮다. PMC-VQA 만 대형·MC·광범위라 예외다.

4. 혼합 비율 결정

GRPO 는 셔플 샘플링을 쓴다. 자연 비율(DeepVision 80%)이면 롤아웃의 80% 가 이미 포화한 데이터다. 그러면 확장 효과가 반으로 준다. 600~1000 step 은 프롬프트 4,800~8,000개만 본다(step 당 8개, 2부 2절). DeepVision 102K 를 다 보지 못한다. 따라서 비율만 중요하고, DeepVision 전량을 넣을 이유가 없다.

Stage-2 ↔ Stage-3 관계 (cascade + replay)

  • Stage-2(검증 가능, accuracy_mix) 다음에 Stage-3(개방형 medix, RaR 심판)를 둔다. Stage-3 init 은 Stage-2 체크포인트다. RLVR 로 추론 습관을 다지고 심판 보상으로 다듬는 커리큘럼이다.
  • 의료 VQA(Stage-2, 검증 가능)와 medix(Stage-3, 개방형)는 상보적이다. 단 출처가 같아(PMC-VQA/SLAKE 는 medix 출처) holdout dedup 이 필수다. 학습 데이터끼리의 중복은 평가를 오염시키지 않는다.
  • 한 단계에서 검증 가능 보상과 심판 보상을 함께 쓰는 방식도 있다. cascade 는 그 방식보다 커리큘럼, 심판 인프라, 디버깅 면에서 단순하다. 망각은 Stage-3 에 검증 가능 데이터 20~30% 를 replay 해 완화한다.

쉬운 설명 (비유)

모델은 한 문제에 답안 4장(그룹)을 낸다. 채점은 답의 점수만 본다. 그룹 평균보다 잘 쓴 답은 확률을 올리고, 못 쓴 답은 확률을 내린다.
PPO 와 달리 별도 채점관(가치망)이 필요 없다. 그룹 평균이 기준선 역할을 한다. 이것이 GRPO 의 핵심 절약이다.

5종 모두 이 그룹 상대 advantage 골격을 공유한다. 차이는 채점을 점수로 바꾸는 규칙에만 있다.

핵심 관점: 5종 = ms-swift 3개 독립 손잡이(knob)의 조합

각 방법은 ms-swift 가 노출하는 직교 손잡이 3개의 좌표로 본다(grpo_trainer.py 손실 분기를 직접 확인). 손잡이마다 겨냥하는 편향이 다르다.

① GRPO / DAPO / Dr.GRPO 요약과 DAPO 기법 4종
  • GRPO(DeepSeekMath, 2024)는 기본형이다. 그룹 평균을 빼고 그룹 std 로 나눠 점수를 만든다. 약점은 두 가지다. std=0 그룹에서는 배우지 못한다(Acc 정체). 긴 답과 쉬운 문제를 과대평가한다.
  • DAPO(ByteDance, 2025)는 GRPO 에 탐색·효율 보강 4종을 더했다. 안정성은 올랐지만 답이 길어져 정확도가 baseline 에 못 미쳤다.
  • Dr.GRPO(2025, "R1-Zero 비판적 분석")는 GRPO 의 편향을 고친다. 손실을 상수로 정규화하고 std 나눗셈을 지운다. DAPO 의 "답 길어짐"을 직접 겨냥한다. 우리 승자다.

② GSPO (시퀀스 IS) 배경과 A/B 결론

GSPO(Group Sequence Policy Optimization, Alibaba/Qwen, 2025-07)는 토큰 단위 IS 를 시퀀스(답안) 단위로 바꾼다.

  • 이유: 토큰 IS 는 응답이 길수록 분산 노이즈가 쌓이고 클립 효과가 커진다. 그러면 붕괴가 생긴다(특히 MoE·장문·LoRA). 시퀀스 우도 비율(길이 정규화)이 이것을 억제한다. 대표 성과는 MoE RL 안정화다.
  • A/B 결론(2026-07-04 중간 집계): 판정창 501~600 에서 dr_grpo(n=100)와 GSPO(n=99)를 비교했다. 두 기법은 사실상 동률이다(중간 집계 Acc 0.500 vs 0.487, 최종 집계는 판정표의 0.487 vs 0.500, reward 0.519 vs 0.506, 차이 ±0.013 노이즈). GSPO 클립이 훨씬 크다(0.185 vs ~0.001). 작은 ε 설계 때문이다.
  • 결정: dr_grpo 를 유지한다(GSPO 미채택). 성능은 동률이다. dr_grpo 는 holdout +73% 가 검증됐고, GSPO 는 on-policy 동률뿐이다. 시퀀스 IS 가 필요한 MoE·초장문 상황도 아니다. 런처는 scripts/launch_gspo_ab.sh(job 59004)다.
③ GDPO (멀티리워드 정규화) 배경과 중간 추세

GDPO(Group reward-Decoupled Normalization, NVIDIA, 2026-01)는 멀티리워드 정규화 문제를 푼다. 여러 보상을 가중합한 뒤 한 번에 정규화하면 서로 다른 조합이 같은 advantage 로 뭉개진다. GDPO 는 보상 함수별로 정규화(z-score)한 뒤 결합한다. AIME 에서 GRPO 대비 +2.3~6.3% 를 보고했다.

  • 적용 이유: 우리는 다중 보상(Stage-2 3종, Stage-3 clinical_judge/format)을 쓰고 스케일이 제각각이다. 이것은 GDPO 가 다루는 경우다. 가장 유망한 적용처는 스케일 차이가 큰 Stage-3(심판 1.0 + 형식 0.2)다.
  • dr_grpo 와의 관계: scale_rewards 만 none→gdpo 로 바꾼 1변수 A/B 다. 나머지 dr_grpo 처리는 그대로다. dr_grpo 가 없앤 ÷std 가 보상 함수별로 되살아난다. 목적은 난이도 편향 회피가 아니라 멀티리워드 균형이다. swift 제약으로 kl_in_reward=True 와 함께 쓸 수 없다. 우리는 KL 을 loss 에 넣으므로 무관하다.
  • 최종 판정: step600 을 완주했다. on-policy 판정창(501~600) Acc 는 dr_grpo 0.487, GDPO 0.490 으로 동률이다. 층화 holdout(N=200)은 0.380 vs 0.390 으로 동률이다(GDPO 미세 우위, 노이즈 내). 상세는 판정표에 있다. Stage-3 용 채택을 권고한다.
