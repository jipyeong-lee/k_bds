4-2. 하이퍼파라미터 축: 왜 절벽인가 (추론)

(a) GDPO 는 붕괴 원인이 아니다 (검증, 2026-08-06 구현 확인). swift/rlhf_trainers/grpo_trainer.py:556 의 산식이다.

elif self.scale_rewards == 'gdpo':
    grouped    = rewards_per_func.view(-1, K, n_func)
    group_std  = nanstd(grouped, dim=1, keepdim=True)          # ← Bessel 보정 (ddof=1)
    normalized = (grouped - group_mean) / (group_std + 1e-8)
    normalized = torch.nan_to_num(normalized, nan=0.0)
    advantages = (normalized * self.reward_weights).sum(dim=1)
    batch_std  = advantages.std() + 1e-8
    advantages = (advantages - advantages.mean()) / batch_std   # ← 배치 전역 whitening

설정은 reward_funcs=['accuracy_mix','format_think','soft_overlong'], reward_weights=[1.0, 0.2, 0.2], kl_in_reward=False 다. kl_in_reward 는 처음부터 False 였다. 따라서 gdpo 강제 비활성 경고는 0회다. 계산에서 놓치기 쉬운 점은 두 가지다.

  1. 표준편차 규약: nanstd 는 Bessel 보정(ddof=1)을 쓴다(utils.py:209). K=4 이진 보상의 실제 σ 는 모집단 값(0.433/0.500)이 아니다. 3:1 이면 0.500, 2:2 이면 0.577 이다.
  2. 배치 전역 whitening: 마지막 줄이 advantage 벡터 전체를 배치 단위로 재정규화한다. 따라서 "gdpo 가 절대 크기를 키운다"는 명제는 성립하지 않는다. 남는 것은 샘플 안의 상대 비율뿐이다.

gdpo 가 바꾸는 것은 형식:정확도 기여 비율이다. 그 배수는 σ_acc / σ_fmt 다.

(a-2) 그룹 균일성 함정도 GDPO 고유 문제가 아니다 (검증). 롤아웃 4개가 모두 형식 위반이면 (r − r̄) = 0 이다. 따라서 none 에서도 형식 기여는 0 이다. gdpo 는 여기에 0/(0+1e-8) = 0 을 더할 뿐이다. 이 함정은 그룹 중심화를 쓰는 GRPO 계열 전체의 성질이다. §8-i ④ 의 실측(전원 F=0 그룹 0.0% → 0.6% → 31.4%, 그 안의 비절단 advantage +0.143)은 유효하다. 다만 그 원인을 GDPO 로 돌리면 안 된다.

  1. §8-i ④ 에서 잡은 실제 병리 그룹은 A 유형(완전 절단 −1.0)이었다. 여기서 gdpo 의 기여는 +15% 뿐이다. scale_rewards=none 이어도 부호와 구조가 같은 +.05/+.05/+.05/−.15 가 나온다. "형식을 어긴 짧은 출력이 양수 advantage 를 받는" 병리는 레시피와 무관하다.
  2. 타이밍(§4-4, 부록 B): 길이와 SoftOverlong 은 step 904 까지 정상이었다(길이 629~1,465, 절단률 0.016~0.078). 길이 폭주는 형식 붕괴(899~904) 직후인 step 905 에 시작했다. 길이는 원인이 아니라 결과다.

(b) 표본 4개로 z-score 3개를 추정한다. 일반 GRPO 는 총합 std 하나만 쓴다. GDPO 는 보상 함수마다 std 를 따로 추정한다. num_generations=4 는 일반 GRPO 기준으로 메모리를 맞춘 값이다. GDPO 는 보상마다 std 를 추정하므로 더 큰 그룹이 유리하다(추론). §8-i ⑤ 의 beta-binomial 외삽에서 임계 구간(851~900)의 전원 형식 실패 그룹은 n=4 의 1.3~1.5% 에서 n=8 의 0.4% 로 준다.

(c) LR 지평. §3-4 에 있다.

(d) overlong_filter 의 앵커 약화. 1부 §3-6, 2부 §8-d 에 있다. step 900–949 에서 rank-step 의 13% 가 앵커에서 빠졌다.

3. epoch 커버리지: 2,337 step 은 0.25 epoch 이다

scripts/launch_stage2_expanded_epoch.sh 는 1 epoch 을 다음처럼 계산했다.

1 epoch = 74,787 / 32(step당 프롬프트: 1 × accum4 × 8gpu) ≈ 2,337 step

이 32 는 프롬프트 수가 아니라 롤아웃 수다. GRPO 에서 per_device_train_batch_size 는 롤아웃을 센다. generation_batch_size 가 None 이므로 TRL/ms-swift 기본식을 쓴다.

generation_batch_size = pdtbs(1) × world_size(8) × steps_per_generation(=grad_accum 4) = 32 completions
프롬프트/step        = 32 ÷ num_generations(4)                                        =  8 prompts
1 epoch              = 74,787 ÷ 8                                                     = 9,348 step

로그가 이 계산을 확인한다. step 627 × 8 = 5,016 행이고, 5,016 / 74,787 = 0.06706 이다. 이 값은 로그의 epoch: 0.06707 과 일치한다. 원래 공식이 맞다면 epoch 은 0.268 이어야 한다.

틀린 것은 라벨과 그 라벨에 기댄 판단이다.

  1. 확장셋의 75% 는 학습에 한 번도 노출되지 않는다. 확장의 핵심이던 MMK12(수학 20%)·PMC-VQA(의료 26%) 추가분 상당량을 학습이 쓰지 않는다.
  2. 중간 평가에서 holdout 이 포화로 보여도, 방법의 한계인지 데이터 미노출 탓인지 구분할 수 없다.
  3. 계획서의 "2 epoch 은 예산의 69% 라 미채택"은 실제로는 0.5 epoch 이야기다. 진짜 1 epoch 은 예산의 134% 라 처음부터 실행할 수 없는 계획이었다.

8-f. holdout 에서의 손상

8 지점 holdout 표(init~1000)는 1부 §2-4 에 있다. 전체 정확도는 850 의 51.52% 에서 900 의 22.63% 로 떨어졌고, 1000 에서는 25.56% 였다.

절벽은 850 → 900 사이 50 step 이다. 짝지음 Δ 는 −28.89pp 다(정답→오답 581 / 반대 69, p<0.0001). step 900 은 step 1000(25.56%)보다도 낮다. 이후 부분 회복이 있었지만 원래 수준으로 돌아오지 못했다.

holdout 에서도 1단계(형식 붕괴)와 3단계(토큰 퇴화)가 따로 보인다. step 900 은 format 0.056 인데 mean_chars 는 2,264 로 정상이다. 이 시점은 순수한 형식 붕괴다. step 1000 에서 mean_chars 가 7,893 으로 뛴다(토큰 퇴화). 이 순서는 §8-b 와 일치한다.

손상은 소스별로 크게 다르다. 850 → 900 짝지음은 의료 −47.50pp, deepvision −30.04pp, 수학 −7.50pp 다(모두 p<0.001). 원인은 채점 방식이다. 의료는 <answer>A</answer> 가 있어야 letter 를 뽑으므로 letter 층이 0.5810 에서 0.1047 로 떨어진다. vl 층은 0.0096 까지 간다. 수학은 본문 어디서든 숫자를 잡아 형식 붕괴에 덜 민감하다. step 900 의 수학은 init 과 구분되지 않는다(0.500 vs 0.4825, p=0.51). deepvision 의 −30.04pp 는 능력 상실보다 형식 상실에 가깝다. 실사용에서는 이 구분이 무의미하다.

형식은 세 소스에서 비슷하게 깨졌다. 취약성 프로브(greedy)의 step 900 형식 실패율은 deepvision 96.7%, mmk12 92.1%, pmcvqa 83.3% 다. 같은 시점 정확도는 수학 50.00, deepvision 16.36, 의료 10.50 으로 갈린다. 손상은 비슷하고, 차이는 채점기가 그 손상을 통과시키는지에서 나온다. step 900 에서 형식이 온전한 문항은 1,772 중 99건(format 0.056)인데 정답은 401건이다. 채점기는 최소 302건(17.0pp)을 <answer> 태그 없이 정답으로 처리했다(§8-i ②).

그림 ①의 두 형식 곡선은 수준을 비교할 수 없다. 지표 정의(느슨한 <answer> 존재 여부 vs 엄격한 FormatThink), temperature(0.0 vs 0.9), 토큰 상한(2,048 vs 6,144)이 모두 다르다. 갈라지는 시점만 읽는다. holdout format 하락(0.947 → 0.89 대)은 길이 인플레이션의 결과다. RL 이 출력을 +16% 늘렸는데 holdout 은 2,048 토큰에서 자른다.
