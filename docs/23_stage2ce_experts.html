요약

전문가 3종의 학습과 확정은 끝났다. 추가 학습 없이 세 전문가를 통합 모델 1개로 합쳤다. 통합 상위 2개의 본평가(전체셋)를 K-BDS 에서 끝냈다. 최종 통합 모델은 ta_w07 로 확정했다.

  1. 전문가 3종을 확정했다: deepvision 2192(B200), mmk12 350, pmcvqa 4896. deepvision 2700 과 mmk12 400 은 탈락시켰다.
  2. 세 전문가는 모두 글로벌 의료 벤치에서 SFT 를 넘었다. 최고는 deepvision 2192 의 57.52%(SFT 46.77%)다.
  3. pmcvqa 전문가는 붕괴 없이 1 epoch 을 끝냈다. 글로벌 벤치 정확도는 46.77% 에서 51.67% 로 올랐다.
  4. deepvision 과 mmk12 는 학습이 길어지면 형식 붕괴가 생긴다. 붕괴 전에 학습↔롤아웃 불일치가 먼저 커진다.
  5. TIS 는 붕괴를 늦춘다. TIS 는 붕괴를 막지 못한다.
  6. 세 전문가의 가중치 변화량(task vector)은 거의 직교한다. 코사인 유사도는 +0.01 ~ +0.11 이다.
  7. 선별 1위는 task arithmetic, 가중치 0.7(ta_w07)이다. 세 도메인에서 전문가 성능의 97~109% 를 지켰다. 2위는 breadcrumbs_d09 다. 10개 중 9개가 판정 기준을 통과했다.
  8. 부호 충돌을 다루는 기법(TIES 등)은 단순 합산보다 낫지 않았다.
  9. 본평가(K-BDS, 전체셋): ta_w07 은 holdout 63.32%(SFT 42.67%), 글로벌 56.22%(SFT 46.77%)다. breadcrumbs_d09 는 holdout 63.71%, 글로벌 56.90% 다. 짝지은 검정에서 차이가 유의하지 않아 더 단순한 ta_w07 을 최종 모델로 확정했다. kgpu 본평가는 플랫폼 장애로 결과 없이 끝났다(C.6).

B.3 X1 — Stage-3 kgpu 스모크

  • 스모크는 완주했다. num_gen 4, completion 1024 에서 38 s/step, 메모리 61.8 GiB.
  • 실제 설정(completion 4096)에서는 84.9 s/step 이다. 1 step 에 프롬프트 2개를 처리한다.
  • 전체 medix 데이터는 약 25 일이 걸린다. 결론: 통합 모델이 생길 때까지 보류한다.

B.4 X2 — deepvision 이어학습과 붕괴

  • job 81708 이 step 2700 까지 완주했다.
  • job 82476 이 이어 돌렸다. lr 이 약 8.2e-6 으로 다시 올라갔다 (max_steps 10000 기준 cosine 재계산).
  • step 3428 에서 형식 붕괴가 생겼다. 학습 정확도는 붕괴 전에 0.55 에서 약 0.45 로 떨어졌다.
  • 결론: 붕괴 전 후보 v2-20261014-111314/checkpoint-2700 을 X6 로 평가했다. 2700 은 holdout 55.6%, 형식 0.765 로 탈락했다. 전문가는 B200 의 2192 다(A.3).

B.5 X3 — mmk12 probe (lr 고정)

  • ckpt-350 에서 lr 1e-5 고정, beta 0.01 로 돌렸다.
  • 형식 점수가 0.89 에서 0.55 로 떨어졌다 (최저 0.28). 정확도는 0.48 에서 0.35 로 떨어졌다.
  • KISTI probe 는 step 351 에서 lr 이 2.0e-6 이었다.
  • 결론: beta 0.01 은 붕괴를 막지 못한다. KISTI probe 가 버틴 것은 lr 감소 덕이다.

B.6 X4 — 붕괴 해부

  1. 실패 응답의 96% 이상이 같은 모양이다. 모델이 </think> 전에 <|im_end|> 를 낸다.
  2. 실패 응답이 받은 advantage 합은 음수다. 보상이 실패를 강화한 것이 아니다.
  3. 붕괴 전에 응답 길이가 줄어든다. deepvision 은 5124 자에서 2396 자, mmk12 는 1972 자에서 1419 자.
  4. 붕괴 전에 불일치 diff 가 커진다. KISTI mmk12: step 1–150 은 0.04, 250 은 0.16, 300 은 0.39, 350 은 0.82. 붕괴는 약 450 에서 생겼다.
  5. 붕괴한 KISTI 실행은 모두 TIS 를 껐다. 2,203 step 을 버틴 B200 deepvision 은 TIS 를 켰다.

B.7 X5 — E1 / E1c

두 실행 모두 붕괴했다. TIS 를 켠 E1 은 붕괴가 약 20 step 늦고, 형식 점수가 덜 떨어졌다.

판정 기준 (실행 전)관측판정
E1c 만 붕괴 → 불일치가 원인아님—
둘 다 붕괴 → TIS 로 부족E1 ~431, E1c ~411 에서 붕괴해당
둘 다 유지 → 환경 차이아님—
해석. 두 실행 모두 불일치가 먼저 커지고, 그 뒤 형식이 무너졌다. TIS 를 켜도 불일치는 커졌다. 그러므로 불일치는 학습 진행에 따라 스스로 커진다. 토큰 단위 절단(TIS)만으로는 붕괴를 막지 못한다. 불일치가 커지는 원인은 확인하지 않았다. 가설은 colocate 모드에서 LoRA 를 vLLM 에 bf16 으로 병합하는 과정이다.
실무 결론. 붕괴 직전 체크포인트를 holdout 으로 골라 전문가로 쓴다. 불일치 지표(log_ppl_abs_diff)를 붕괴 조기 경보로 감시한다.

Part C. 전문가 통합 (모델 merging)

추가 학습 없이 전문가 3종을 합쳐 통합 모델 1개를 만들었다. 단순 가중 합산(task arithmetic w=0.7)이 가장 좋았다.

C.1 질문과 판정 기준

질문: 추가 학습 없이 세 전문가를 한 모델로 합칠 수 있는가? 판정 기준은 실행 전에 정했다(docs/21_stage2a_design.html §8).

  1. 각 도메인에서 전문가 성능의 90% 이상을 지킨다.
  2. 글로벌 벤치에서 SFT 보다 높다.
  3. 두 기준을 통과한 후보 중 (holdout + 글로벌)/2 가 높은 순서로 2개를 본평가한다.

원래 설계(8/13)는 3단계다: 계단 0 = 가중치 merging(학습 없음) → 계단 1 = 순차 증류 → 계단 2 = 도메인별 교사 증류(OPD). 1차에서는 계단 0 을 했다.

C.3 진단: task vector 코사인 유사도

세 도메인의 τ 는 거의 직교한다. 그러므로 합산해도 서로 간섭이 작을 것으로 예측했다.

  • 계산법: ΔW 를 만들지 않고 r×r 연산으로 정확히 구한다. ⟨B₁A₁, B₂A₂⟩ = Σ (B₁ᵀB₂) ∘ (A₁A₂ᵀ).
  • τ 의 크기(‖ΔW‖): deepvision 1.24, pmcvqa 1.21, mmk12 0.73.

kgpu 실행 절차

  1. KISTI 에서 데이터, 체크포인트, 모델을 tar 로 묶는다.
  2. KISTI 에서 kgpu ~/files 로 바로 PUT 한다.
  3. pod 를 만든다. 이미지는 nvidia/cuda:12.9.1-cudnn-devel-ubuntu24.04 다.
  4. 스크립트를 pod 로컬로 복사한다.
  5. pod 에서 스크립트를 background 로 실행한다.
  6. 감시 스크립트가 180 초마다 로그를 읽는다.
  7. 스크립트가 끝나면 감시 스크립트가 pod 를 반납한다 (trap … EXIT, 상한 10 시간).

확인하지 않은 것

  • 불일치가 커지는 원인. 오프라인 측정(병합 LoRA 대 학습 엔진 확률 비교)으로 확인할 수 있다. 예상 비용은 약 1 시간, 3천 크레딧.
  • 시퀀스 단위 rejection 이나 lr 감쇠가 붕괴를 막는지.
  • kgpu(sdpa) 와 KISTI(flash_attn) 의 불일치 수준 차이. E1c 의 첫 구간 diff(0.27)는 E1(0.13)의 2배였다. 같은 체크포인트이므로 이 차이는 측정 잡음일 수 있다.
  • DELLA 를 다른 인자(ε 0.05 등)로 돌리면 동작하는지.
  • w = 0.6, 0.8 같은 중간 가중치.
  • 전문가 평가 환경 차이(KISTI A100 대 kgpu RTX 5090)의 크기. 재측정(pod ex)은 kgpu 장애로 끝나지 않았다.
