# DeepSeek-V4 파이프라인 도입안 — 순차 RL 을 전문가 병렬 + 증류로

> 작성 2026-08-13 · 근거 = [DeepSeek-V4 (arXiv 2606.19348)](https://arxiv.org/html/2606.19348v1) ·
> [2026년 모델 서베이](rlvr_survey_2026.md) · ms-swift 4.13 설치본 소스 직접 확인
>
> **결론 먼저**: 도입할 수 있고, 뜻밖에 잘 맞는다. 다만 **가장 비싼 단계(통합)에 거의 공짜인
> 근사가 존재**하므로 그것부터 시험해야 한다. 그리고 리포트가 통합 손실을 명시하지 않는다는
> 사실을 알고 시작해야 한다.

---

## 0. 리포트에서 확인된 것과 안 된 것

정직하게 먼저 적는다. **DeepSeek-V4 리포트는 후처리 부분이 얇다.**

| 항목 | 리포트 서술 |
|---|---|
| 2단 구조 | ✅ 명시 — "독립적 도메인 전문가 육성 → 온폴리시 증류로 단일 모델 통합" |
| 도메인 | ✅ 수학·코딩·에이전트·지시따르기 |
| 전문가 학습법 | ✅ 도메인별 SFT → **GRPO** + 도메인별 보상모델 |
| 통합 손실 | ⚠️ "**reverse KL**" 과 "**Full-Vocabulary OPD**" 라는 표현만. **수식 없음** |
| 교사 가중·하이퍼파라미터 | ❌ 미기재 |
| 전문가 대 통합모델 성능 비교 | ❌ **수치 없음** |
| 후처리 안정성 | ❌ 없음 (사전학습 쪽만 — Anticipatory Routing, SwiGLU Clamping) |

> **따라서 "DeepSeek-V4 를 따라 한다"는 건 구조를 따라 한다는 뜻이지 레시피를 복제한다는
> 뜻이 될 수 없다.** 통합 손실의 세부는 우리가 정해야 하고, 그 근거는 다른 데서 와야 한다.
> [Kimi K3](https://arxiv.org/abs/2607.24653) 가 같은 구조(MOPD)를 **수식까지 공개**했으므로
> 세부는 그쪽을 참조하는 게 낫다.

## 1. DeepSeek-V4 가 실제로 하는 것

```
                    ┌→ SFT(수학)     → GRPO(수학 보상)     → 전문가 ┐
  base model ───────┼→ SFT(코딩)     → GRPO(코딩 보상)     → 전문가 ┼→ 온폴리시 증류 → 단일 모델
                    ├→ SFT(에이전트) → GRPO(에이전트 보상) → 전문가 ┤   (전어휘 reverse KL,
                    └→ SFT(지시)     → GRPO(지시 보상)     → 전문가 ┘    학생 자기 롤아웃 위에서)
```

핵심은 두 가지다.

1. **전문가끼리 서로를 보지 않는다.** 도메인 간 간섭이 학습 중에 발생하지 않는다.
2. **통합은 가중치 평균이 아니라 행동 증류다.** 학생이 **자기 롤아웃**을 만들고, 그 위에서
   교사 분포와의 KL 을 맞춘다. 토큰 단위 추정이 아니라 **전어휘** 손실을 쓰는 게 안정성의 핵심 —
   전문가들이 불일치할 때 그래디언트가 튀지 않는다.

Kimi K3 의 MOPD 는 같은 구조를 보상 형태로 쓴다(공개된 수식):

```
r_opd(y_t) = clip( sg( log π_teacher(y_t|·) / π_student(y_t|·) ), −R_max, +R_max )
```

즉 **교사·학생 로그확률비를 토큰별 밀집 보상**으로 쓰고, 기존 RL 인프라에 그대로 얹는다.

## 2. 우리 상황에 얹으면

### ① 전문가 A 가 이미 있다 🔴

`checkpoint-850` 이 곧 일반 도메인 전문가다. **이미 검증됐다.**

| | 값 |
|---|---|
| 홀드아웃 전량(n=1,772) | **51.52%** |
| init 대비 | **+8.18pp** (p<0.0001) |
| step 400 대비 | +2.48pp (p=0.020) |
| 붕괴 이전인가 | ✅ 붕괴는 899~904. 850 은 깨끗하다 |

### ② 전문가 B 는 어차피 해야 하는 일이다

Stage-3(의료 RaR)는 계획서의 핵심 산출물이고 배선·루브릭·judge·스모크가 전부 PASS 상태로 대기 중이다.

> **여기서 구조가 바뀐다.** 지금 계획은 Stage-2 결과물 **위에** Stage-3 를 올리는 순차다.
> DeepSeek-V4 구조에서는 Stage-3 를 **`sft_mixed_merged` 에서 따로** 올린다.
> 추가 작업이 아니라 **출발점만 바꾸는 것**이다.

### ③ LoRA 라서 전문가가 어댑터다 🔴

이게 가장 큰 행운이다. `checkpoint-850/adapter_config.json` 확인:

```
peft_type       LORA
r / alpha       16 / 32
base_model      /home01/k252a02/kbds_project/work/checkpoints/sft_mixed_merged
target_modules  ^(model\.language_model(?=\.).*\.(q_proj|k_proj|v_proj|o_proj|
                  gate_proj|up_proj|down_proj|in_proj_*))$
adapter 크기    173 MB  (≈ 43M 파라미터, 9B 의 0.48%)
```

전문가 B 도 **같은 base·같은 rank·같은 target_modules** 로 학습하면:

- 교사를 메모리에 올리는 비용이 **전체 모델 사본이 아니라 어댑터 173MB** 다
- 그리고 **두 어댑터가 같은 모양이라 산술 연산이 가능하다** — 아래 §5 계단 0 의 근거

```
        DeepSeek-V4 (1.6T MoE)              우리 (9B + LoRA)
  전문가 = 전체 모델 사본 ×4            전문가 = 어댑터 173MB ×2
  통합   = 반드시 증류 필요             통합   = 어댑터 산술이 먼저 가능
```

## 3. 실현 가능성 — ms-swift 4.13 점검

설치본 소스를 직접 읽었다(`swift/rlhf_trainers/gkd_trainer.py`, 1,071줄).

### 되는 것

| 필요 | ms-swift | 확인 지점 |
|---|---|---|
| 온폴리시 증류 | `--rlhf_type gkd` | `rlhf_args.py:229` |
| **학생 자기 롤아웃** | `--lmbda 0.5` — 확률 λ 로 학생이 생성한 응답으로 학습 | `gkd_trainer.py:491` |
| **전어휘 KL/JSD** | `generalized_jsd_loss`, top-k 없이 full-vocab 모드 | `:774`, `:231` |
| forward/reverse KL 보간 | `--beta` (0=forward, 1=reverse, 0.5=JSD) | `:838` |
| **멀티모달** | `is_multimodal` 분기 + vLLM 생성 경로 | `:257`, `:629` |
| vLLM 가속 생성 | `--use_vllm true` | `:507` |
| LoRA 자기증류 최적화 | `disable_adapter()` 로 베이스를 교사로 재사용(사본 없음) | `:88`, `:406` |
| 원격 교사 | `--teacher_model_server` (멀티모달도 지원) | `:615` |

### 안 되는 것 — 두 개의 갭 ⚠️

**갭 ①: 다중 교사 미지원.** `rlhf_type=gkd` 는 교사를 **하나만** 받는다.
DeepSeek-V4 의 "여러 전문가 → 한 학생"을 그대로 못 한다.

**갭 ②: `teacher_adapters` 가 배선되지 않았다.** 인자는 선언돼 있으나
(`rlhf_args.py:68`) 실제 교사 구성 지점은 다른 걸 읽는다:

```python
# pipelines/train/rlhf.py:94
adapters = args.adapters if key == 'ref' else args.reward_adapters
model = prepare_adapter(args, model, adapters)      # key=='teacher' 여도 reward_adapters
```

> 전문가 LoRA 를 교사로 올리려면 **`--teacher_adapters` 가 아니라 `--reward_adapters`** 로
> 넘겨야 한다. 스모크로 반드시 확인할 것. 아니면 위 한 줄 패치.

## 4. 무엇이 전이되고 무엇이 안 되는가

**전이되는 것**

- ✅ **구조적 논거**. 그리고 우리 데이터가 이미 순차의 대가를 보여준다 —
  Stage-2 는 일반 **+8.18pp**, **의료 +0.75pp (p>0.5, n=400, ±3.5pp)**. 여섯 지점 전부 미검출.
- ✅ **독립 육성의 이점**. Stage-3 를 ck-850 위에 올리면 검증된 +8.18pp 를 잃을 위험이 있다.
  따로 올리면 그 위험이 구조적으로 사라진다.
- ✅ **인프라**. GKD 가 전어휘·온폴리시·멀티모달을 전부 지원한다.

**전이되지 않을 수 있는 것 — 정직하게**

- ⚠️ **규모 차이가 크다.** DeepSeek-V4 는 1.6T MoE(49B 활성)다. 도메인 간 간섭은 **용량이
  충분할 때** 전문가 분리로 푸는 문제다. 우리 학습 가능 파라미터는 **43M(0.48%)** 이다.
  전문가 분리의 이득이 같은 크기로 나온다는 보장이 없다.
- 🚨 **통합 용량 문제.** 어댑터 두 개의 행동을 **같은 rank 16 공간**에 밀어 넣어야 한다.
  → **완화책: 학생 rank 를 올린다(r=32 또는 48).** 메모리 비용은 무시할 수준이다.
  이건 우리 상황에만 있는 손잡이다.
- ⚠️ **리포트에 전문가 대 통합모델 비교 수치가 없다.** 통합이 전문가 성능을 얼마나
  보존하는지 원저자도 공개하지 않았다. **우리가 직접 재야 한다.**
- ⚠️ **우리 도메인은 2개고 서로 가깝다.** DeepSeek 의 수학/코딩/에이전트/지시는 훨씬 이질적이다.
  일반과 의료가 가까우면 분리의 이득이 작고, 대신 **병합이 쉬워진다** — §5 계단 0 에 유리하다.

## 5. 계단식 계획 — 공짜부터

가장 비싼 단계(증류)에 거의 공짜인 근사가 있다. **순서를 지켜야 돈을 아낀다.**

### 계단 0 — 어댑터 산술 병합 (GPU 비용 ≈ 평가분만)

두 전문가가 같은 base·rank·target_modules 의 LoRA 이므로 **직접 더할 수 있다.**

```
ΔW_merged = α · ΔW_general + (1−α) · ΔW_medical        # 선형 보간
```

α 를 {0, 0.25, 0.5, 0.75, 1} 로 훑고 홀드아웃(n=1,772)으로 잰다. 필요하면 TIES/DARE 로 확장.

- **비용**: 학습 0. 평가 5회 × 홀드아웃 = 수 GPU-h
- **판정**: 두 도메인 성능이 각 전문가의 **90% 이상** 보존되면 여기서 끝낸다
- **왜 될 수 있나**: 우리 두 도메인이 가깝고, LoRA 는 저계수 갱신이라 선형성이 상대적으로 잘 성립한다

> 🔴 **이 계단을 건너뛰면 안 된다.** 되면 증류 비용 전체를 아낀다.
> 안 되더라도 **"얼마나 안 되는지"가 증류의 기준선**이 된다.

### 계단 1 — 순차 GKD (재고 ms-swift, 패치 없음)

계단 0 이 부족하면. 학생을 두 교사에 **순차로** 증류한다.

```
학생 ← GKD(교사=일반 전문가)  →  학생' ← GKD(교사=의료 전문가)
```

- **비용 추정**: 아래 §6
- **위험**: 두 번째 증류가 첫 번째를 잊는다. **완화** = 2회차에 일반 데이터를 섞고 λ 를 낮춘다
- **장점**: ms-swift 재고 기능만 쓴다

### 계단 2 — 도메인 라우팅 다중 교사 (패치 필요)

DeepSeek-V4 에 가장 가까운 형태. **샘플의 source 라벨로 교사를 고른다.**

우리 데이터셋은 이미 source 가 붙어 있다(deepvision 일반 / mmk12 수학 / pmcvqa 의료).
`gkd_trainer.py` 의 교사 forward 앞에 어댑터 스왑을 넣는 **수십 줄 패치**다.

- **위험**: 업스트림 수정. apptainer 파손 상태라 컨테이너 재빌드 불가 → `loader` 모드에서
  site-packages 직접 수정이 되는지 확인 필요
- **여기까지 갈 필요가 있는지는 계단 0·1 결과로 정한다**

## 6. 비용

기준: **벽시계 330 s/it**(재현 실험 74583 실측, `step_time` 163s 가 아님) · 1 벽시계시 = **8 GPU-h**

| 항목 | 산출 | GPU-h | 예산(5,000) 대비 |
|---|---|---:|---:|
| 전문가 A **재학습**(850 step) | 850×330s = 78 벽시계h | **623** | 12.5% |
| 전문가 A **재사용**(ck-850) | — | **0** | 0% |
| 전문가 B (Stage-3 의료 RL, 400 step 가정) | 400×330s = 37 벽시계h | **293** | 5.9% |
| 계단 0 어댑터 병합 + 평가 5회 | 평가만 | **~20** | 0.4% |
| 계단 1 순차 GKD (300 step ×2회) | ~250 s/it 추정 × 600 = 42 벽시계h | **333** | 6.7% |

> **GKD step time 은 추정이다.** 근거: 롤아웃이 프롬프트당 1개(GRPO 는 4개)라 생성 비용이
> 약 1/4, λ=0.5 라 절반 배치만 생성, 대신 교사 forward 1회 추가. **스모크로 반드시 실측할 것.**
>
> ⚠️ **큐 대기가 실질 비용이다.** 재현 실험은 제출 후 **5일 13시간** 대기했다.
> 계단을 잡으로 쪼갤수록 대기가 곱해진다 — **계단 0 은 평가 잡 하나에 다 넣을 것.**

### 전문가 A 를 재학습할 것인가

| | 재사용(ck-850) | 재학습(`stable` recipe) |
|---|---|---|
| 비용 | 0 | 623 GPU-h + 큐 대기 |
| 성능 | 검증된 +8.18pp | 미지 — 붕괴 없이 850 을 넘길 수 있으면 더 높을 수도 |
| 보상 수정 반영 | ❌ 안 됨 | ✅ 됨 |

**ck-850 은 붕괴 이전 구간이라 보상 버그의 영향을 받지 않았다.** 형식 결합 문제는
형식을 잃었을 때만 발동하는데, 850 시점 형식은 0.895 로 멀쩡했다.

> **권고: 전문가 A 는 ck-850 을 그대로 쓴다.** 623 GPU-h 와 5.5일 대기를 아끼고,
> 그 예산을 전문가 B(= 계획서의 실제 산출물)와 통합 실험에 쓴다.
> 재학습은 계단 0·1 결과를 보고 **필요하다고 판명되면** 그때 한다.

## 7. 권고 실행 순서

```
지금 ─┬─ [1] Stage-3 의료 RL 을 sft_mixed_merged 에서 시작 → 전문가 B
      │       (계획서 산출물이자 DeepSeek-V4 구조의 전문가 B. 어차피 해야 하는 일)
      │       ⚠️ ck-850 위가 아니라 SFT 베이스 위에서 — 이게 유일한 구조 변경이다
      │
      └─ [2] 그동안 계단 0 준비: 어댑터 병합 스크립트 + 평가 잡 1개로 묶기
              (전문가 B 없이는 병합할 게 없으므로 준비만)

B 완성 후 ─→ [3] 계단 0 실행 (병합 α 스윕 5점 + 홀드아웃 평가) — ~20 GPU-h
                 ├─ 90% 이상 보존 → 끝. 증류 불필요
                 └─ 미달 → [4] 계단 1 순차 GKD (스모크로 step time 실측 먼저)
```

**당장 필요한 결정은 하나다** — **Stage-3 를 `sft_mixed_merged` 에서 시작할 것인가,
`checkpoint-850` 에서 시작할 것인가.** 이것만 정하면 나머지는 뒤로 미룰 수 있다.

| | `sft_mixed_merged` 에서 (DeepSeek-V4 구조) | `checkpoint-850` 에서 (현행 계획) |
|---|---|---|
| 일반 +8.18pp | 전문가 A 에 보존됨 | Stage-3 가 훼손할 수 있음 |
| 의료 출발점 | SFT 베이스 (홀드아웃 의료 57.25%) | ck-850 (58.00%, **차이 미검출**) |
| 통합 단계 | 필요 | 불필요 |
| 되돌리기 | 언제든 순차로 전환 가능 | 훼손되면 되돌릴 수 없음 |

> 의료 출발점 성능이 **57.25% 대 58.00% 로 통계적 차이가 없다**(사후분석 홀드아웃 표).
> **즉 Stage-3 를 ck-850 위에 올려서 얻는 의료 이득은 측정된 바 없다.**
> 반면 잃을 것(+8.18pp 일반)은 측정돼 있다. **비대칭이 명확하다.**
