### 핵심 의사결정 (요약)
- **NVLink 없음 → 전 단계 LoRA** (full-FT 375~660s/step → LoRA ~5배↑).
- **추론 길이 폭주 → 간결 콜드스타트** (ZeRO-3 길이확대는 5배 느려 불채택). **Ablation으로 필수성 입증**(없으면 base→RL 형식0 붕괴·홀드아웃 0.18).
- **형식보상 천장 발견 → 콜드스타트 v3 재설계**(2026-07-16). v2 데이터 자체가 `format_think` **0.473**(느슨한 `closed()` 필터 + "가장 짧은 것" 선별이 찍기를 우선) → RL 형식 0.425 정체의 진짜 원인. **게이트를 1.0 으로 강제** + 프로젝트 최초로 **의료 CoT 투입**(medix 는 추론 트레이스가 0건).
- **데이터는 반드시 받아서 실측 후 채택**(2026-07-16). 이름·초록으로 고르면 틀린다 — S-Chain("Structured Visual CoT for Medicine")은 실제로 **고유정답 3개**, MMFineReason 은 trace 중앙값 **9~11K자**, MMK12/MM-Eureka 는 **추론 trace 자체가 없음**. 전부 다운로드·파싱 후에야 드러남.
- **plateau 돌파 → dr_grpo** (두 정규화 편향 제거로 zero-std plateau 통과). GSPO·GDPO도 A/B로 검증 → 동률(GDPO만 Stage-3용 채택).
- **평가 누수 차단 → 층화 홀드아웃 + fresh 1 epoch 재학습** (기존 stride 슬라이스는 학습 파일과 겹침).
- **Stage-3 → 정적 RaR 루브릭** (인스턴스식 대비 시각근거 변별 우세).

"평평하다"가 아니라 "큰 상승은 없다"까지가 한계이고 **판정선 +3pp 는 배제되지 않는다.** 08-03 에 적었던 "200 step 당 1~2pp → 잔여 +8~16pp" 기대 상단은 이 구간과 **양립하지 않는다**(기대 이득이 그때보다 작다). ⓒ **의료(pmcvqa) 네 지점 전부 무변화**: init 대비 +0.25 / −0.75 / −0.25 / +1.25pp, 모두 p>0.5. n=100(±9.8pp)의 "0.57→0.53 하락"은 **재현되지 않았다** — 하락이 아니라 **무변화**이고 n=400(±3.5pp)에서도 그대로다. 반면 수학은 +8~11pp 로 뚜렷 → **RLVR 이 수학은 밀어주지만 의료 MC 는 못 밀어준다**가 확정에 가까워졌고, 이는 **Stage-3 의 우선순위를 올린다.** ③ **부수 관찰 — 형식·길이의 대가**: format **0.947 → 0.887~0.903(−6pp)**, mean_chars **1,812 → ~2,100(+16%)**. 08-03 의 길이 구성효과(장문 deepvision 15.1% vs 비장문 44.2%)와 같은 방향이고, 전체 정확도가 오르는 와중에도 누적된다. ④ **`plot_holdout_paired.py` 신설**: 기존 `plot_eval_trend.py` 는 소스별 n 을 `d["n"] // 3` 으로 잡아 전량(972/400/400)에서 deepvision 오차막대가 틀리고, 집계 jsonl 만 읽어 **비짝지음 CI 밖에** 못 그린다. 문항별 파일에서 직접 3패널(궤적 / init 대비 Δ / step400 대비 Δ+판정선)을 그리고 `eval_paired.py` 와 교차검증해 수치 일치 확인. **점별 오차막대가 겹치는 것을 "차이 없음"으로 읽는 오독을 막으려고 Δ 패널을 분리**했다. ⑤ **`eval_midtrain.slurm` 버그 수정**: `EVAL_STAGES=init` 인데도 스냅샷+병합이 **무조건** 실행돼, `MID_CKPT` 미지정 시 **학습 중인 디렉터리에서 최신 checkpoint 를 자동 선택**해 복사·병합했다. 쓰이지도 않는 5분 낭비인 데다 기록 중인 체크포인트를 집을 위험. `if has_stage trained` 로 감싸고 중복 `has_stage` 정의 제거(job 74187 제출 전 발견). ⑥ **`watch_and_eval.sh` 신설 — step 1200 감시 자동화**: `save_total_limit=5` 라 체크포인트는 저장 후 ~20h 뒤 롤링 삭제되는데 step 1200 도달이 **밤 22:30 경**이라 사람이 그 창에 붙어야 했다. 로그인 노드에서 5분 간격 폴링 → 30초 크기 안정성 확인(쓰는 중인 것 회피) → **전체 `cp -a`** → `sbatch` 제출. 재개로 v1→v2 가 돼도 글롭이 잡는다. **스냅샷이 제출보다 먼저**라 sbatch 가 실패해도 체크포인트는 안전하다. checkpoint-1000 으로 감지·복사·무결성(`diff -rq`) 시험 완료, `sbatch --test-only` 통과. ⑦ 덤으로 **step 1000 평가 제출**(job 74300) — `debug-1gpu` 유휴 + 시험용 스냅샷 재활용. 700~1200 의 500 step 공백이 절반으로 줄어든다. ⑧ 학습은 **step 1,038/2,337 (44.4%)**, 73925 가 25h 경과(한도 70h), 벽시계 ~296 s/it.

- **08-04 (2)** — 🚨 **학습 붕괴 발견 → 체인 취소. step 850 이 최고점.** ① **발견 경위**: 재시작 파라미터를 정하려고 `frac_reward_zero_std` 를 확인하다가 인접 지표에서 드러났다. **홀드아웃 추세만 보고 있었으면 못 봤다** — 마지막 홀드아웃 측정점이 700 이었고 붕괴는 900 에서 일어났다. ② **붕괴 경과**: step ~900 에서 `FormatThink` 가 0.90 → **0.057** 로 급락(25 step 구간 평균), 길이 1,970 → 3,032 → 6,704, 절단률 5.9% → 20.5% → **38.1%**, KL 0.036 → 0.107 → 최종 **0.541**, 엔트로피 0.55 → 0.10. 최근 스텝은 `reward` 가 **음수**(−0.045)였다. ③ **두 단계 붕괴**: **1단계(~900) 형식만 무너진다** — 이 시점 롤아웃은 정상 추론을 하고 `</think><answer>14</answer>` 대신 `Answer: 14` 로 끝낼 뿐이다(퇴화율 0.1%). **2단계(~1000+) 토큰 퇴화** — `AAAA…` 4만 자, `<think>` 태그 1,497회 같은 출력(퇴화율 16.8%, 길이 p90 **41,341자**). **"추론이 길어서 잘렸다"도 "같은 말을 반복했다"도 아니다**: 추론이 없고 반복 단위가 토큰 한 개다 → 토큰 상한을 늘려도 소용없다. ④ **방아쇠 = 정방향 되먹임**: 정확도 보상이 형식과 **결합**돼 있다(`AccuracyMix` 가 `<answer>(.*?)</answer>` 로 답을 뽑음 → 실측 Acc(F=0) 0.02~0.26 vs Acc(F=1) 0.46~0.50). 형식 이탈 → 정확도까지 0 → 그룹 advantage 가 "정답이냐"가 아니라 "형식을 지켰냐"로 지배 → 업데이트 확대(grad_norm 0.023→0.117, clip_hi 4배, KL 3배) → 더 이탈 → **절벽(step 899→903)**. 넘어간 뒤 90%가 0점이라 `reward_std` 가 **0.074** 로 주저앉아 복원력이 사라진다. lr 은 cosine 으로 매끄럽게 감쇠(7.03e-06→6.74e-06) — 방아쇠 아님. ⑤ **유력한 근인 — `overlong_filter=True`**: ms-swift 4.1.3 이 잘린 completion 을 `completion_mask` 에서 제외하는데 **그 마스크가 KL 계산에도 그대로 쓰인다**(`grpo_trainer.py` L1132). 즉 길이 폭주로 잘리기 시작하면 그 샘플은 **손실 그래디언트도 KL 앵커도 안 받는다** — 절단률 38% 구간에서 배치의 1/3 이 면제된 셈. 보상(SoftOverlong −1)은 형제를 밀어**올릴** 뿐 퇴화를 밀어**내리지** 않는다.
