## 2. 파이프라인에서의 위치

```
① 콜드스타트 SFT  →  ② 범용 RLVR  →  ③ 의료 특화 RL(RaR)  →  ④ 평가
   ✅ 완료             🚀 지금 여기        ⏳ 미시작(핵심 산출물)     🔄 기준선 확보
   형식 주입           검증가능 정답        개방형 의료 VQA          HealthBench
   LoRA SFT           GRPO/GDPO           GRPO + 루브릭 judge
```

- **② 의 입력** = ① 의 산출 `sft_mixed_merged`(v3 콜드스타트). 이 문서에서 **`init`(RL 0%)** 로 부른다.
- **② 의 역할** = 정답이 기계적으로 검증되는 문제로 **추론 습관을 다지는** 단계.
  깊은 의료 추론은 ③(개방형·judge 채점)이 전담한다. ②를 의료 MC로 과적하면 패턴매칭을 학습할 위험이 있어 의료 비중을 26%로 제한했다.

## 3. 방법론 — 왜 dr_grpo + GDPO 인가

### 계보: 각 논문이 직전 방법의 무엇을 고쳤나

| 방법 | 겨냥한 한계 | 해결책 |
|---|---|---|
| **GRPO** (2402.03300) | PPO의 **가치망(critic)** 이 정책망만큼 커서 메모리·연산 부담 | critic 제거. 한 문제에 답안 여러 장을 뽑아 **그룹 내 상대 보상**을 advantage 로 |
| **DAPO** (2503.14476) | 엔트로피 붕괴 · 후반 gradient 소실 · 길이 폭주 | Clip-Higher · **Dynamic Sampling** · token-level loss · overlong shaping |
| **Dr.GRPO** (2503.20783) | GRPO 의 두 편향 — ÷시퀀스길이(**길이 편향**), ÷그룹std(**난이도 편향**) | 두 정규화 **삭제** → unbiased 추정 |
| **GSPO** (2507.18071) | 토큰 단위 IS 의 장문 **분산 누적** | IS 를 **시퀀스 단위**로 |
| **GDPO** (2601.05242) | **다중 보상** 가중합 후 통짜 정규화 → 조합이 같은 advantage 로 붕괴 | 결합 **전에 보상별 개별 z-score** → 보상 간 상대차 보존 |

### 5종을 3개 손잡이의 좌표로 본다

ms-swift 가 노출하는 **직교 3-knob** 조합으로 정리하면 외울 것이 없다.

| 손잡이 | 무엇을 바꾸나 | 선택지 |
|---|---|---|
| `loss_type` | 손실 정규화·클리핑 | `grpo`(÷길이) · `dapo`(÷배치토큰+clip-higher) · **`dr_grpo`**(÷상수) |
| `importance_sampling_level` | IS 단위 | **`token`** · `sequence`(=GSPO) |
| `scale_rewards` | advantage 정규화 | `group`(÷std) · `none`(=dr_grpo) · **`gdpo`**(보상별 개별 z-score) |

**채택 = `(dr_grpo, token, gdpo)`.** dr_grpo 가 A/B 승자였고, GDPO 는 거기서 `scale_rewards` 하나만 바꾼 1-knob 변형이다.

### clean A/B 결과 (기법 외 전 조건 동일, 한 스크립트에서 env 토글)

| 방법 | 결과 |
|---|---|
| GRPO (baseline) | plateau — Acc 0.500 정점 후 정체, zero_std 0.24→0.33 |
| DAPO | 안정(zero_std 0)하나 **미돌파** Acc 0.465, 길이 재폭주 |
| **dr_grpo** ✅ | **돌파·승자** Acc **0.526**, 길이 억제 |
| **GDPO** ✅ | dr_grpo 의 1-knob 변형, 멀티리워드 균형 → **본실행 채택** |
| GSPO | 열세 |

> ⚠️ 위 수치는 **구 데이터셋·구 홀드아웃** 기준이다. 현재 확장셋 수치(§7)와 같은 그래프에 올리면 안 된다.

## 5. 학습 세팅

### 하드웨어 제약이 방법을 정했다

| | |
|---|---|
| 노드 | **8 × A100 80GB PCIe**, **NVLink 없음**(`nvidia-smi topo -m` 전부 PHB) → GPU P2P 차단, NCCL 이 호스트 RAM(SHM) 폴백 |
| 결과 | full fine-tuning 은 18GB gradient all-reduce 병목 → 9B 모델인데도 **375~660초/step** |
| **대응** | **전 단계 LoRA** — adapter gradient(수십 MB)만 통신 → **약 128초/step**, 5~75배 개선. base 동결이라 DeepSpeed 없이 DDP 로 충분 |
| OS | CentOS 7.9 / glibc 2.17 → 최신 vLLM 설치 불가 → **컨테이너 스택**(2026-07-27 apptainer 파손 후 loader 우회 운용) |

### 실행 하이퍼파라미터 (job 73924 실제 값)

| 구분 | 값 |
|---|---|
| 베이스 / init | Qwen3.5-9B (`qwen3_5`) / v3 콜드스타트 `sft_mixed_merged` |
| 튜닝 | LoRA **rank 16 · alpha 32 · all-linear** · bf16 |
| 알고리즘 | **dr_grpo 손실 + GDPO** · IS `token` · ε 0.2 · KL **β 0.04** |
| 보상 | `accuracy_mix` **1.0** + `format_think` **0.2** + `soft_overlong` **0.2** |
| 샘플링 | `num_generations` **4** · temperature **0.9** · `enable_thinking` |
| 필터 | `dynamic_sample`(재샘플 최대 3) · `overlong_filter` |
| 배치 | pdtbs 1 × accum 4 × 8 GPU = **32 completions/step → 프롬프트 8/step** |
| 길이 | `max_completion_length` 6,144 · `soft_cache_length` 2,048 · `max_length` 10,240 |
| 최적화 | lr **1e-5** · gradient checkpointing · flash-attn |
| 롤아웃 | vLLM **colocate** · TP 1 · gpu_mem_util 0.4 · sleep_level 1 |
| 스케줄 | `max_steps` **2,337** · save_steps 50 · save_total_limit 5 |

**출력 형식**: `<think>간결 추론</think><answer>최종답</answer>` (`\boxed{}` 미사용).
내장 `accuracy` 보상은 객관식 letter 를 파싱하지 못해 DeepVision 의 약 48%에서 보상이 통째로 소실된다 →
**커스텀 `accuracy_mix`**(수식은 math_verify, letter·문자열은 정규화 일치)로 분기 처리했다.

> ⚠️ **`max_steps=2,337`은 1 epoch 이 아니라 0.25 epoch 이다.**
> GRPO 에서 `per_device_train_batch_size` 는 프롬프트가 아니라 completion 을 센다 →
> 프롬프트/step = 32 ÷ `num_generations`(4) = **8** → 1 epoch = 74,787 ÷ 8 = **9,348 step**.
> 종전 문서의 "1 epoch = 2,337 step" 은 `÷ num_generations` 누락이었다(2026-08-02 정정).
> 진짜 1 epoch 은 약 6,694 노드시간 = 예산의 134% 로 애초에 실행 불가능하다.

이걸로 "더 학습하면 오르나"를 답할 수 있을 것으로 봤는데, 결과는 아니었다.

![소스별 학습 정확도 추세](assets/stage2_source_trend.png)

**① 최근 상승은 대부분 길이 구성이다.** 장문 completion 은 정답률이 훨씬 낮다(39.4% vs 44.6%).

원 계열의 최근 점프 +2.4pp 중 장문 제외 후 남는 것은 **+0.8pp**(t=0.64, 미검출).

**② 결정에 필요한 "지금부터의 기울기"는 판별되지 않는다.**

| 소스 | step 301~750 기울기 (장문 제외) | 잔여 1,587 step 외삽 |
|---|---|---|
| deepvision | −0.047 pp/100step (t=−0.11) | **−0.7pp** [95% **−14.4 ~ +12.9**] |
| mmk12 수학 | +0.195 (t=+0.17) | +3.1pp [−31.7 ~ +37.9] |
| pmcvqa 의료 | +0.906 (t=+1.23) | +14.4pp [−8.5 ~ +37.2] |

세 소스 모두 0 을 크게 포함한다. **표본 24,000 건으로도 그렇다** —
스텝 간 분산이 커서 기울기의 유효 표본은 "완성문 24,000" 이 아니라 "스텝 450 개"에 가깝기 때문이다.
정확도의 **수준**을 재는 것과 **기울기**를 재는 것은 다른 문제이고, 결정에 필요한 것은 후자다.

> 엔트로피는 안 꺾였고 KL 도 작아 정책 자체는 건강하다. 문제는 모델이 아니라 **측정**이다.
> *(교란요인 확인: `dataset_shuffle=True` — 학습셋이 소스순 정렬이라 필수 / 최종 epoch 0.25 라 문항 재등장 없음 = fresh-sample / 재개 구간 751~787 중복 제거)*

**자원**: `step_time` 합계 29.0h 대 실제 경과 58.2h → **절반이 학습 밖**(vLLM 롤아웃 생성·재샘플링·체크포인트). GRPO colocate 의 구조적 비용.

## 7. 중간 홀드아웃 평가 — 전량 1,772 짝지음 (2026-08-04)

![Stage-2 홀드아웃 전량 평가](assets/stage2_holdout_paired.png)

확장 홀드아웃을 **전량 1,772건**(deepvision 972 / mmk12 400 / pmcvqa 400) 사용해
`init·400·500·600·700` 다섯 지점을 **동일 문항·greedy(temperature 0)** 로 채점하고,
문항별 점수를 저장해 **짝지음(McNemar)** 으로 비교했다. 검출 하한이 **8.0pp → 1.7~2.3pp**.

| (%) | **init**(RL 0%) | step 400 | step 500 | step 600 | step 700 |
|---|---:|---:|---:|---:|---:|
| **전체** (n=1,772) | **43.34** | 49.04 | 49.55 | 49.32 | **50.40** |
| deepvision 일반 (n=972) | 35.60 | 42.59 | 43.11 | 42.08 | 44.44 |
| mmk12 수학 (n=400) | 48.25 | 56.25 | 58.25 | 59.25 | 56.75 |
| **pmcvqa 의료** (n=400) | 57.25 | 57.50 | 56.50 | 57.00 | 58.50 |
| format(`<answer>`) | 0.947 | 0.892 | 0.887 | 0.887 | 0.903 |

| 짝지음 Δ | 전체 | deepvision | 수학 | 의료 |
|---|---|---|---|---|
| init → 400 | **+5.70pp** p<0.0001 ✅ | +7.00 ✅ | +8.00 ✅ | +0.25 ✗ |
| init → 700 | **+7.05pp** p<0.0001 ✅ | +8.85 ✅ | +8.50 ✅ | +1.25 ✗ |
| **400 → 700** | +1.35pp p=0.18 ✗ | +1.85 ✗ | +0.50 ✗ | +1.00 ✗ |

### 읽기

**① RL 은 확실히 듣는다.** init → 400 **+5.70pp, p<0.0001**. 같은 비교가 n=300 에서는
"+3.67pp, p=0.428, 판정불가"였다 — 효과가 없던 게 아니라 **±9.8pp 노이즈에 묻혀 있었다.**
(콜드스타트 SFT 의 base 0.2500 → init 0.4533 = **+20.3pp, p<0.001** 도 여전히 유효하다. 단 그 값은 n=300 층화 기준이다.)

**② 그러나 그 이득은 step 400 까지에 거의 다 실렸다.** 400 이후 세 구간이 모두 미검출이고,
가장 간격이 큰 400 → 700(300 step)조차 **+1.35pp(p=0.18)** 다.
다만 이것도 "평평하다"가 아니라 **95% 구간 [−0.6, +3.3]pp** 다 — 큰 상승은 배제되지만 +3pp 는 아니다.

**③ 의료는 네 지점 전부 움직이지 않았다.** init 대비 +0.25 / −0.75 / −0.25 / +1.25pp, 모두 p>0.5.
n=100(±9.8pp) 시절의 "0.57 → 0.53 하락"은 **재현되지 않았다** — 하락이 아니라 **무변화**다.
반면 수학은 +8~11pp 로 뚜렷하다. **검증가능 정답 RLVR 이 수학은 밀어주지만 의료 MC 는 못 밀어준다**는 그림이 n=400 에서도 그대로다.

**④ 형식·길이는 대가를 치렀다.** format **0.947 → 0.89**(−6pp), mean_chars **1,812 → ~2,100**(+16%).
전체 정확도가 오르는 와중에도 이 손실은 누적된다.

**⑤ 남은 질문은 하나로 좁혀졌다 — "400 이후로 더 오르는가".**
400 vs 1200 의 검출 하한이 **±1.9pp** 이므로 실제 Δ 가 +3pp 라면 step 1200 에서 검출된다.
그 측정이 §8 판정의 유일한 근거다.

> ⚠️ 그림 왼쪽 패널의 **점별 오차막대는 비짝지음**이라 서로 겹친다 — 그걸 보고 "차이 없다"고 읽으면 안 된다.
> 판정축은 가운데·오른쪽 짝지음 패널이다.
> ⚠️ 전량은 소스 가중이 **55/23/23** 이라 층화 n=300(각 33.3%)의 전체값과 **직접 비교 불가**다.
> init 이 0.4533(n=300) vs 0.4334(전량)로 다른 것은 가중치 차이지 측정 오차가 아니다. 소스별 수치는 언제나 비교 가능하다.
